Publique em todas as suas contas direto do seu sistema

A API faz tudo o que o painel faz: conectar contas de Instagram, Facebook e TikTok, subir fotos e vídeos, agendar a mesma publicação em dezenas de contas com legenda própria ou variações automáticas, acompanhar o resultado conta a conta, ver o desempenho e receber avisos por webhook. Funciona com qualquer linguagem e com n8n, Make ou Zapier.

Começo

Comece em 5 minutos

Este é o caminho completo de uma integração: gerar a chave, conferir, pegar as contas, subir um vídeo, testar e agendar. No fim tem o script inteiro em três linguagens.

  1. Gere a chave de acesso. No painel, abra Config → API e integrações, dê um nome que diga onde ela vai ser usada (ex.: n8n, site) e clique em Gerar chave. Só o dono ou um admin do time vê esse botão.
    A chave aparece uma vez só. Copie na hora e guarde no gerenciador de senhas ou nas variáveis de ambiente do seu sistema. Se perder, revogue e gere outra.

    No terminal, deixe a chave numa variável para os exemplos funcionarem do jeito que estão:

    # macOS / Linux
export INSTAFLOW_KEY="ifk_cole_a_sua_chave_aqui"

# Windows (PowerShell)
$env:INSTAFLOW_KEY = "ifk_cole_a_sua_chave_aqui"
  2. Confira se está tudo certo chamando GET /me. Se voltar 200 com o nome do time, a chave e o endereço estão certos. 
    curl "{BASE}/me" -H "Authorization: Bearer $INSTAFLOW_KEY"
  3. Pegue os ids das contas com GET /accounts. Cada conta tem um id que começa com spc_: é ele que vai na publicação. Quer mandar para um grupo inteiro? Use GET /groups e o campo group_ids.
  4. Suba o vídeo: POST /media/upload-url devolve um endereço para enviar o arquivo (upload_url) e o link que ele vai ter (media_url). Envie o arquivo com PUT e guarde o media_url. Se o arquivo já está num link público https, pule este passo e use o link direto.
  5. Teste sem publicar: mande a publicação para POST /posts com "dry_run": true. A API confere as regras de cada rede, mostra o horário final e as legendas de cada conta, e não publica nada.
  6. Agende de verdade: tire o dry_run e mande de novo, com um cabeçalho Idempotency-Key (evita publicação dobrada se a sua internet cair no meio). Guarde o id que voltar.
  7. Acompanhe: cadastre um webhook para receber post.published e post.failed de cada conta, ou consulte GET /posts/{post_id}.

O script inteiro

Sobe video.mp4, pega as contas conectadas de Instagram e TikTok e agenda um Reels com uma legenda diferente para cada conta. Troque a data e a legenda pelas suas.

#!/usr/bin/env bash
# bash publicar.sh   (precisa de curl e jq; a chave em INSTAFLOW_KEY)
set -euo pipefail
BASE="{BASE}"
AUTH="Authorization: Bearer $INSTAFLOW_KEY"
api() { curl -sS --fail-with-body "$@" -H "$AUTH"; }

# 1) conferir a chave
api "$BASE/me" | jq -r '"time: " + .team.name'

# 2) ids das contas conectadas de Instagram e TikTok
CONTAS=$(api "$BASE/accounts?status=connected" | jq -c '[.data[] | select(.platform == "instagram" or .platform == "tiktok") | .id]')

# 3) subir o vídeo
UP=$(api -X POST "$BASE/media/upload-url")
curl -sS --fail-with-body -X PUT "$(jq -r .upload_url <<< "$UP")" -H "Content-Type: video/mp4" --data-binary @video.mp4
VIDEO=$(jq -r .media_url <<< "$UP")

# 4) montar a publicação (horário sem fuso = horário da Bahia)
POST=$(jq -n --arg video "$VIDEO" --argjson contas "$CONTAS" '{
  caption: "Promoção de sexta: tudo com 20% off! 🔥\n\n#ofertas",
  placement: "reels",
  media: [{url: $video, kind: "video"}],
  account_ids: $contas,
  scheduled_at: "2026-09-20T18:00",
  vary_captions: true
}')

# 5) testar sem publicar e depois agendar de verdade
api -X POST "$BASE/posts?dry_run=true" -H "Content-Type: application/json" -d "$POST" | jq '.caption_overrides'
api -X POST "$BASE/posts" -H "Content-Type: application/json" -H "Idempotency-Key: $(uuidgen)" -d "$POST" | jq '{id, status, scheduled_at}'
// node publicar.mjs   (Node 18+; a chave em INSTAFLOW_KEY)
import { readFile } from "node:fs/promises";
import { randomUUID } from "node:crypto";

const BASE = "{BASE}";

async function api(caminho, { method = "GET", body, headers = {} } = {}) {
  const resposta = await fetch(BASE + caminho, {
    method,
    headers: {
      Authorization: `Bearer ${process.env.INSTAFLOW_KEY}`,
      ...(body ? { "Content-Type": "application/json" } : {}),
      ...headers,
    },
    body: body ? JSON.stringify(body) : undefined,
  });
  const dados = await resposta.json();
  if (!resposta.ok) throw new Error(`${resposta.status} ${dados.code ?? ""} ${dados.error}`);
  return dados;
}

// 1) conferir a chave
const eu = await api("/me");
console.log("time:", eu.team.name);

// 2) ids das contas conectadas de Instagram e TikTok
const { data: contas } = await api("/accounts?status=connected");
const ids = contas.filter((c) => ["instagram", "tiktok"].includes(c.platform)).map((c) => c.id);

// 3) subir o vídeo
const { upload_url, media_url } = await api("/media/upload-url", { method: "POST" });
const envio = await fetch(upload_url, { method: "PUT", headers: { "Content-Type": "video/mp4" }, body: await readFile("video.mp4") });
if (!envio.ok) throw new Error(`upload falhou: ${envio.status}`);

// 4) montar a publicação (horário sem fuso = horário da Bahia)
const publicacao = {
  caption: "Promoção de sexta: tudo com 20% off! 🔥\n\n#ofertas",
  placement: "reels",
  media: [{ url: media_url, kind: "video" }],
  account_ids: ids,
  scheduled_at: "2026-09-20T18:00",
  vary_captions: true,
};

// 5) testar sem publicar e depois agendar de verdade
const teste = await api("/posts", { method: "POST", body: { ...publicacao, dry_run: true } });
console.log("vai sair assim:", teste.caption_overrides);
const post = await api("/posts", { method: "POST", body: publicacao, headers: { "Idempotency-Key": randomUUID() } });
console.log("agendada:", post.id, post.status, post.scheduled_at);
# python publicar.py   (pip install requests; a chave em INSTAFLOW_KEY)
import os
import uuid
import requests

BASE = "{BASE}"
AUTH = {"Authorization": f"Bearer {os.environ['INSTAFLOW_KEY']}"}

def api(metodo, caminho, headers=None, **kw):
    resposta = requests.request(metodo, BASE + caminho, headers={**AUTH, **(headers or {})}, timeout=60, **kw)
    dados = resposta.json()
    if not resposta.ok:
        raise RuntimeError(f"{resposta.status_code} {dados.get('code')} {dados.get('error')}")
    return dados

# 1) conferir a chave
print("time:", api("GET", "/me")["team"]["name"])

# 2) ids das contas conectadas de Instagram e TikTok
contas = api("GET", "/accounts", params={"status": "connected"})["data"]
ids = [c["id"] for c in contas if c["platform"] in ("instagram", "tiktok")]

# 3) subir o vídeo
up = api("POST", "/media/upload-url")
with open("video.mp4", "rb") as arquivo:
    requests.put(up["upload_url"], data=arquivo, headers={"Content-Type": "video/mp4"}, timeout=600).raise_for_status()

# 4) montar a publicação (horário sem fuso = horário da Bahia)
publicacao = {
    "caption": "Promoção de sexta: tudo com 20% off! 🔥\n\n#ofertas",
    "placement": "reels",
    "media": [{"url": up["media_url"], "kind": "video"}],
    "account_ids": ids,
    "scheduled_at": "2026-09-20T18:00",
    "vary_captions": True,
}

# 5) testar sem publicar e depois agendar de verdade
teste = api("POST", "/posts", json={**publicacao, "dry_run": True})
print("vai sair assim:", teste["caption_overrides"])
post = api("POST", "/posts", json=publicacao, headers={"Idempotency-Key": str(uuid.uuid4())})
print("agendada:", post["id"], post["status"], post["scheduled_at"])
Pronto. A publicação aparece no painel (Calendário e Fila) do mesmo jeito que as criadas lá. Tudo o que a API faz fica visível para o time.
Começo

Autenticação e chaves de acesso

Toda chamada leva a chave no cabeçalho Authorization, depois da palavra Bearer:

curl "{BASE}/accounts" \
  -H "Authorization: Bearer ifk_a1B2c3D4e5F6g7H8i9J0k1L2m3N4o5P6q7R8s9T0"

A chave começa com ifk_ e tem 44 caracteres. Ela pertence a um time: enxerga as contas, publicações, grupos e a biblioteca do time em que foi criada. Não precisa (nem dá) informar o time na chamada.

Tipos de chave

Ao gerar a chave você escolhe o que ela pode fazer. As opções se combinam.

ConfiguraçãoO que a chave pode fazerQuando usar
Leitura e escrita (padrão)Tudo o que o painel faz, menos criar e revogar chaves.Integração que publica: n8n, Make, seu sistema, seu app.
Só leituraSó chamadas GET. Qualquer outra volta 403 somente_leitura. Não vê o segredo dos webhooks.Painéis de resultado, relatórios, BI, planilhas.
Presa a algumas contasSó lista, publica e acompanha as contas marcadas. Não conecta contas novas. Publicação com conta de fora volta 403 conta_bloqueada.Um cliente, loja ou filial que só pode mexer nas contas dele.
Chamadas por minutoDe 10 a 600 (padrão 120). Passou, volta 429 limite_chamadas.Proteger a sua conta de um loop no seu código.

Criar, trocar e revogar

  • Criar e revogar só pelo painel, em Config → API e integrações, e só o dono ou um admin do time. Pela API, /keys responde 403 so_painel.
  • Até 20 chaves ativas por time. Cada linha mostra quando a chave foi usada pela última vez e quantas chamadas fez nas últimas 24 horas.
  • Revogar vale na hora: a próxima chamada com ela volta 401 chave_revogada. Não dá para desfazer.

Trocar uma chave sem parar a integração

  1. Gere uma chave nova com o mesmo tipo.
  2. Coloque a nova no seu sistema (variável de ambiente, credencial do n8n etc.).
  3. Confira com GET /me que o sistema já está usando a nova (o campo key.prefix mostra o começo dela).
  4. Revogue a antiga.

Cuidados de segurança

  • Nunca coloque a chave em código que roda no navegador ou no celular de outras pessoas (site público, app), nem em repositório de código. Quem tem a chave publica nas suas contas.
  • Use uma chave por integração, com um nome que diga onde ela está. Se uma vazar, você revoga só ela.
  • Prefira só leitura e presa a contas sempre que a integração não precisar de mais.
  • O InstaFlow guarda só uma impressão digital (hash SHA-256) da chave. Depois de criada, ninguém consegue ver a chave de novo, nem o suporte.
  • Suspeitou de vazamento? Revogue na hora e gere outra. Os registros de uso mostram os endereços IP das chamadas.
Painel e API usam as mesmas rotas. O painel entra com o login da pessoa; a API entra com a chave. Por isso tudo o que a API faz aparece no painel na hora, e vice-versa.

Listas e paginação

Listas voltam dentro de data, com meta dizendo onde você está. Use limit (até 100) e offset para andar pelas páginas enquanto has_more for true.

{
  "data": [ { "id": "6f1d2c8a-3b1e-4f7a-9d2c-8e5b4a1c0f37", "status": "scheduled" } ],
  "meta": { "limit": 25, "offset": 0, "total": 61, "has_more": true }
}
// busca todas as páginas de uma lista
async function todas(caminho) {
  const itens = [];
  for (let offset = 0; ; offset += 100) {
    const pagina = await api(`${caminho}${caminho.includes("?") ? "&" : "?"}limit=100&offset=${offset}`);
    itens.push(...pagina.data);
    if (!pagina.meta.has_more) return itens;
  }
}
const agendadas = await todas("/posts?status=scheduled");

Cabeçalhos das respostas

CabeçalhoO que diz
X-Request-IdIdentificador desta chamada. Guarde nos seus registros e mande para o suporte quando algo der errado.
X-RateLimit-LimitQuantas chamadas por minuto a chave pode fazer.
X-RateLimit-RemainingQuantas ainda restam neste minuto.
X-RateLimit-ResetQuando o minuto vira (segundos desde 1970, UTC).
Idempotent-Replayedtrue quando a resposta é a repetição de uma chamada anterior com a mesma Idempotency-Key.

Datas, vazios e compatibilidade

  • Datas em ISO 8601. Nas respostas, sempre em UTC (terminam em Z ou +00:00). Veja Datas e horários.
  • null quer dizer "sem valor" (ex.: permalink antes de publicar).
  • Na v1 nenhum campo é removido nem muda de nome. Campos e eventos novos podem aparecer: o seu código deve ignorar o que não conhece.
Conceitos

Erros e novas tentativas

Quando algo dá errado, a resposta tem status HTTP de erro e um JSON assim:

{
  "error": "Instagram: Reels precisa de exatamente um vídeo.",
  "code": "conta_bloqueada",
  "details": null
}
  • error: o que aconteceu, em português, pronto para mostrar a quem usa o seu sistema.
  • code: código estável para o seu código decidir o que fazer. Não vem em erros de validação simples (400 sem código): aí a mensagem explica o campo.
  • details: só quando o erro veio do serviço que publica nas redes; traz a resposta original dele.

O que fazer em cada caso

StatusSignificaO seu sistema deve
400O pedido não passou nas regras.Mostrar a mensagem e corrigir. Não repetir igual.
401Chave ausente, errada ou revogada.Conferir a variável da chave; gerar outra se preciso.
403A chave não tem permissão para isso.Usar uma chave de escrita ou sem restrição de contas.
404O item não existe neste time (ou nas contas da chave).Conferir o id.
409Conflito de Idempotency-Key, ou IA desligada no modo ai.Ver o code: esperar e repetir, ou usar chave nova.
429Limite de chamadas por minuto.Esperar até X-RateLimit-Reset e diminuir o ritmo.
5xxFalha temporária nossa ou das redes.Tentar de novo com espera crescente (1 s, 2 s, 4 s…) e a mesma Idempotency-Key.

Todos os códigos

Tentar de novo sem publicar duas vezes

// repete só o que vale repetir (429 e 5xx), sempre com a MESMA Idempotency-Key
async function comRetentativa(fazer, tentativas = 4) {
  for (let i = 0; ; i++) {
    const resposta = await fazer();
    const podeRepetir = resposta.status === 429 || resposta.status >= 500;
    if (!podeRepetir || i === tentativas - 1) return resposta;
    const reset = Number(resposta.headers.get("X-RateLimit-Reset"));
    const espera = resposta.status === 429 && reset ? Math.max(1000, reset * 1000 - Date.now()) : 1000 * 2 ** i;
    await new Promise((pronto) => setTimeout(pronto, espera));
  }
}

const idem = crypto.randomUUID(); // gerada uma vez para esta publicação
const resposta = await comRetentativa(() => fetch("{BASE}/posts", {
  method: "POST",
  headers: {
    Authorization: `Bearer ${process.env.INSTAFLOW_KEY}`,
    "Content-Type": "application/json",
    "Idempotency-Key": idem,
  },
  body: JSON.stringify(publicacao),
}));

Conceitos

Idempotência: nunca publicar duas vezes

Imagine: o seu sistema manda POST /posts, a internet cai antes da resposta chegar e você não sabe se a publicação foi criada. Se repetir, pode publicar duas vezes, e post repetido em série pode fazer a rede restringir a conta.

A solução é mandar o cabeçalho Idempotency-Key com um valor único para aquela operação. Se a mesma chamada chegar de novo com o mesmo valor, a API devolve a primeira resposta e não faz nada de novo.

IDEM=$(uuidgen)   # gere uma vez e reutilize nas tentativas

curl -X POST "{BASE}/posts" \
  -H "Authorization: Bearer $INSTAFLOW_KEY" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: $IDEM" \
  -d @publicacao.json
# repetir o mesmo comando devolve a MESMA resposta, com o cabeçalho Idempotent-Replayed: true

Regras

  • Vale para qualquer POST: publicar, reenviar, criar grupo, registrar mídia, cadastrar webhook.
  • Mesma chave, mesma rota e mesmo corpo em até 24 horas: volta a resposta guardada (mesmo status, mesmo corpo) com Idempotent-Replayed: true.
  • Mesma chave com corpo ou rota diferente: 409 idempotencia_conflito. Cada operação precisa de uma chave nova.
  • A primeira ainda está rodando: 409 idempotencia_em_andamento. Espere alguns segundos e repita com a mesma chave.
  • Respostas 5xx, 409 e 429 não ficam guardadas: dá para repetir com a mesma chave. Respostas 400 ficam (repetir igual daria o mesmo erro): corrija o pedido e use uma chave nova.
  • A chave tem até 255 caracteres visíveis, sem espaço. O ideal é um UUID novo por operação. Chaves valem por time.
Receita segura: gere a Idempotency-Key no momento em que a publicação nasce no seu sistema (ex.: quando o pedido é salvo) e guarde junto com o registro. Toda tentativa de envio daquele registro usa a mesma chave.

Datas e horários

O InstaFlow trabalha no horário da Bahia (America/Bahia, UTC−3, sem horário de verão). Em scheduled_at você pode mandar a hora "de parede" ou uma data com fuso:

null, "now" ou sem o campoPublicar agoranull
  • O horário precisa estar no futuro (aceita até 1 minuto de atraso do seu relógio).

  • As respostas trazem datas em UTC. Para mostrar no horário da Bahia:

  .format(new Date(post.scheduled_at)); // "20/09/2026, 18:00"

Requisitos de mídia de cada rede

A API confere na hora as regras de quantidade e combinação (ex.: Reels com exatamente um vídeo). Já as regras do arquivo (formato, duração, tamanho, proporção) são conferidas pela rede no momento de publicar: se o arquivo estiver fora, aquela conta aparece como falha com o motivo. Seguindo as tabelas abaixo, isso não acontece.

Vídeo que funciona em todas as redes de uma vez

Um arquivo com estas características serve para Reels do Instagram, Reels do Facebook e TikTok ao mesmo tempo:

  • MP4, vídeo H.264, áudio AAC 48 kHz estéreo, 30 fps;
  • 1080 × 1920 (9:16), entre 5 e 90 segundos, até 100 MB;
  • com o índice no começo do arquivo (faststart), para a rede começar a ler rápido.

Para converter qualquer vídeo para esse padrão com o ffmpeg:

ffmpeg -i entrada.mov \
  -c:v libx264 -profile:v high -pix_fmt yuv420p -r 30 -b:v 8M -maxrate 10M -bufsize 16M \
  -vf "scale=1080:1920:force_original_aspect_ratio=decrease,pad=1080:1920:(ow-iw)/2:(oh-ih)/2" \
  -c:a aac -b:a 128k -ar 48000 -ac 2 \
  -movflags +faststart saida.mp4

Links de mídia

  • Precisam ser https, públicos (abrir numa aba anônima sem login) e apontar para o arquivo em si, não para uma página (link de visualização do Google Drive ou Dropbox não serve).
  • O link precisa continuar funcionando até a publicação sair em todas as contas. Para agendamentos, prefira subir pelo POST /media/upload-url: o arquivo fica guardado com a gente.
  • Fotos que passaram pelo WhatsApp perdem resolução. Use o arquivo original.
Publicar

Ciclo de uma publicação

Uma publicação é um post que vai para uma ou várias contas. Ela tem um estado geral (status) e cada conta tem o seu próprio resultado: uma conta pode falhar enquanto as outras publicam.

POST /posts→scheduled→ no horário →processing→processed

Estado da publicação (status)

statusQuer dizerO que dá para fazer
scheduledAgendada, esperando o horário.Editar, mudar o horário ou cancelar.
processingSaindo agora nas contas.Acompanhar; conferir.
processedO envio terminou. Veja o resultado de cada conta.Reenviar as que falharam; ver o desempenho.
canceledCancelada antes de sair.Nada (continua no histórico).
errorNão chegou a ser enviada.Criar de novo.

Resultado em cada conta (results[].status)

statusQuer dizerAviso (webhook)
pendingEsperando o horário ou a rede terminar.—
publishedSaiu. permalink tem o link do post e platform_post_id o id na rede.post.published
failedNão saiu. error explica o motivo em português.post.failed

Quando todas as contas têm resultado, sai uma vez o aviso post.completed com os totais e o status final: published (todas), partial (algumas) ou failed (nenhuma).

Linha do tempo

  1. POST /posts responde 201 com status: "scheduled" (ou "processing" se for para agora).
  2. No horário, o envio começa e cada conta publica por conta própria (vídeos podem levar alguns minutos a mais).
  3. A cada conta que termina, chega post.published ou post.failed e GET /posts/{post_id} já mostra o resultado.
  4. Com todas prontas, chega post.completed. Se algo falhou, veja o motivo e use reenviar ou crie uma publicação nova com o arquivo corrigido.
  5. Os números do post (visualizações, curtidas…) começam a aparecer em GET /metrics/posts em até 3 horas.
Depois que começou a sair, não dá mais para editar nem cancelar. Para corrigir um post já publicado, edite ou apague direto no aplicativo da rede.

Legendas

  • caption é a legenda de todas as contas: até 2.200 caracteres, com emojis, #hashtags e @menções.
  • No JSON, quebra de linha é \n e aspas dentro do texto são \". Toda boa biblioteca faz isso sozinha quando você monta o objeto e usa JSON.stringify (JavaScript) ou json= (Python).

Guia prático

Variações de legenda: uma diferente para cada conta

O mesmo texto em muitas contas parece repetição para as redes e para quem segue mais de uma conta. As variações reescrevem a legenda para cada conta, com o mesmo sentido.

Jeito 1: direto na publicação

Mande "vary_captions": true no POST /posts. A primeira conta fica com a legenda original e cada outra ganha uma versão. Contas que você já colocou em caption_overrides ficam com a sua legenda. A resposta mostra as legendas escolhidas e um resumo em variations.

{
  "caption": "Continue firme, Big! Vamos juntos pela Bahia 💪 #Bahia #44144",
  "account_ids": ["spc_Lj3Kd82hQx1mNp4", "spc_Pq8Wm2Zt6Rv9Yb3", "spc_Tk5Hn7Jd1Lc3Vx8"],
  "media": [{ "url": "https://data.postforme.dev/…/foto", "kind": "image" }],
  "vary_captions": true,
  "dry_run": true
}
Use dry_run para ler antes. Com "dry_run": true as variações já aparecem em caption_overrides na resposta, sem publicar. Gostou? Mande a mesma coisa sem o dry_run (as versões são geradas de novo) ou copie o caption_overrides que voltou para publicar exatamente aquelas.

Jeito 2: gerar, revisar e publicar

  1. Chame POST /captions/vary com a legenda e quantas versões quer (normalmente o número de contas menos 1).
  2. Mostre as versões para alguém aprovar ou editar no seu sistema.
  3. Publique mandando as aprovadas em caption_overrides.

Com IA ou sem IA

modeComo geraQuando usar
auto (padrão)A IA do time reescreve; se ela não estiver ligada, falhar ou devolver menos versões, o gerador automático completa e warning avisa.Quase sempre.
aiSó a IA. Sem IA ligada, 409 sem_ia; com cota esgotada, 429.Quando você prefere erro a uma variação mais simples.

O gerador automático não inventa frases: numa legenda curta, com pouca coisa para trocar, algumas versões só ganham um emoji (o campo weak conta quantas). Para reescrita de verdade em legendas curtas, ligue a IA.

O que nunca muda

  • Números (preços, porcentagens, datas, números como 44144), @menções, links e o conjunto de #hashtags (a ordem pode mudar). Versão da IA que mexa nisso é descartada.
  • Cor de coração e bandeiras de emoji. A IA não pode acrescentar fatos, promessas ou hashtags.
  • Versão igual à original, ou diferente só em emoji e pontuação, é descartada.

Ligar a IA (grátis com o Google)

  1. Entre em aistudio.google.com/apikey com uma conta Google e clique em Create API key.
  2. Copie a chave (começa com AIza).
  3. No InstaFlow, abra Config → Variações de legenda com IA, cole e clique em Salvar e testar. Só o dono ou um admin faz isso.

Também aceita chaves da Groq (gsk_), OpenAI (sk-), Anthropic (sk-ant-) e OpenRouter (sk-or-). A chave fica guardada no servidor e nunca volta para o navegador nem para a API (GET /ai mostra só o começo e o fim). Chaves do GitHub não servem: o GitHub não gera texto. No plano grátis do Google, os textos enviados podem ser usados por ele para melhorar os produtos.

Contas e grupos

Conectar uma conta pelo seu sistema

  1. Chame POST /accounts/connect com a rede (instagram, facebook ou tiktok).
  2. Abra o url que voltar no navegador de quem é dono da conta. A autorização usa a conta que estiver aberta naquele navegador.

Avisos

Webhooks: receba um aviso quando algo acontecer

Em vez de ficar perguntando se já publicou, cadastre uma URL do seu sistema. O InstaFlow manda um POST com JSON para ela a cada evento.

Cadastrar

  • No painel, em Config → API e integrações → Webhooks, ou pela API com POST /webhooks.
  • A URL precisa ser https. Até 10 webhooks por time, cada um com os eventos que quiser.
  • Guarde o segredo (whsec_…) que aparece ao cadastrar: é com ele que você confere que o aviso veio mesmo do InstaFlow.

O corpo sempre tem id, type, created_at, team_id e data. Exemplos de cada evento:

Responder, repetições e ordem

  • Responda com qualquer status 2xx em até 10 segundos. Tem trabalho pesado? Guarde o evento e processe depois.
  • Sem 2xx (ou sem resposta), tentamos de novo: 3 tentativas (na hora, depois de 1 s e depois de 5 s).
  • 50 eventos seguidos sem sucesso pausam o webhook. Corrija a URL e ative de novo no painel (ou PUT /webhooks/{webhook_id} com "active": true).
  • O mesmo evento pode chegar mais de uma vez: ignore id repetido.
  • A ordem não é garantida. Use created_at e, na dúvida, confira em GET /posts/{post_id}.
  • Cada entrega fica registrada por 30 dias: GET /webhooks/{webhook_id}/deliveries.

Conferir a assinatura

  1. Leia o corpo cru, exatamente como chegou (antes de transformar em JSON).
  2. Do cabeçalho X-InstaFlow-Signature, separe t e v1.
  3. Calcule HMAC-SHA256 com o segredo do webhook sobre o texto t + "." + corpo, em hexadecimal.
  4. Compare com v1 usando comparação de tempo constante. Diferente = recuse.
  5. Recuse também se t estiver a mais de 5 minutos do seu relógio (protege contra reenvio de avisos antigos).
// Node + Express: npm install express
import crypto from "node:crypto";
import express from "express";

const app = express();
const SEGREDO = process.env.INSTAFLOW_WEBHOOK_SECRET; // whsec_…
const processados = new Set(); // em produção, guarde no seu banco

// express.raw: o corpo chega cru, do jeito que foi assinado
app.post("/webhooks/instaflow", express.raw({ type: "application/json" }), (req, res) => {
  const assinatura = req.get("X-InstaFlow-Signature") ?? "";
  const t = /t=(\d+)/.exec(assinatura)?.[1];
  const v1 = /v1=([0-9a-f]{64})/.exec(assinatura)?.[1];
  const corpo = req.body.toString("utf8");
  const esperado = crypto.createHmac("sha256", SEGREDO).update(`${t}.${corpo}`).digest("hex");
  const confere = t && v1 && crypto.timingSafeEqual(Buffer.from(v1, "hex"), Buffer.from(esperado, "hex"));
  if (!confere || Math.abs(Date.now() / 1000 - Number(t)) > 300) return res.status(400).send("assinatura inválida");

  const evento = JSON.parse(corpo);
  res.sendStatus(200); // responde logo e processa em seguida
  if (processados.has(evento.id)) return;
  processados.add(evento.id);

  if (evento.type === "post.published") console.log("publicou em", evento.data.username, evento.data.permalink);
  if (evento.type === "post.failed") console.log("falhou em", evento.data.username, evento.data.error);
  if (evento.type === "post.completed") console.log("terminou:", evento.data.status, evento.data.targets);
});

app.listen(3000);

Integrações

n8n, Make e Zapier

Qualquer ferramenta que faça uma chamada HTTP conversa com a API. O segredo é sempre o mesmo: cabeçalho Authorization com Bearer e a chave, e corpo em JSON.

n8n

  1. Credencial: em Credentials → New → Header Auth. Name: Authorization. Value: Bearer ifk_… (com a palavra Bearer e um espaço).
  2. Chamar a API: nó HTTP Request → Method POST → URL {BASE}/posts → Authentication: Generic Credential Type → Header Auth → a credencial. Ligue Send Body, escolha JSON e cole o corpo, usando expressões para os valores que vêm de nós anteriores.
  3. Evitar duplicado: em Send Headers, adicione Idempotency-Key com um valor único do item (ex.: {{ $json.id }}-{{ $json.data }}). Se o fluxo rodar de novo, não publica duas vezes.
  4. Subir arquivo: um HTTP Request POST {BASE}/media/upload-url; depois outro HTTP Request com Method PUT, URL {{ $json.upload_url }}, Body n8n Binary File (o campo binário do arquivo) e o cabeçalho Content-Type do arquivo; por fim use o media_url no corpo da publicação, com "kind": "video" ou "image".
  5. Receber avisos: nó Webhook (POST), copie a Production URL e cadastre em Config → API e integrações → Webhooks. Ative o fluxo.

Make

  1. Módulo HTTP → Make a request. URL: {BASE}/posts. Method: POST.
  2. Headers: Authorization = Bearer ifk_… (e, se quiser, Idempotency-Key).
  3. Body type: Raw. Content type: JSON (application/json). Request content: o JSON da publicação. Marque Parse response.
  4. Para receber avisos: módulo Webhooks → Custom webhook, copie a URL e cadastre no InstaFlow.

Zapier

  1. Ação Webhooks by Zapier → Custom Request. Method: POST. URL: {BASE}/posts.
  2. Data: o JSON da publicação. Headers: Authorization = Bearer ifk_… e Content-Type = application/json.
  3. Para receber avisos: gatilho Webhooks by Zapier → Catch Hook, copie a URL e cadastre no InstaFlow.
Guarde a chave como credencial, nunca escrita direto num campo que outras pessoas do workspace veem.

Versões

Histórico de versões

1.4.0 · 23/09/2026

  • POST /captions/vary aceita styles: um estilo de escrita por versão (tom, público, gírias). Com ele, a resposta mantém a posição de cada versão.
  • vary_captions no POST /posts usa o estilo salvo em cada conta (painel: Contas → Estilo).
  • Variações da IA precisam mudar o texto: versão que só troca emoji, pontuação ou um detalhe numa legenda longa é descartada, e a IA tenta de novo uma vez para as que faltaram.
  • O modelo da IA agora é escolhido pelo dono ou admin em Config (com a lista de modelos da chave e, no OpenRouter, o preço de cada um) e não muda sozinho.

1.3.0 · 22/09/2026

  • Plano do Post for Me passou de 1.000 para 2.500 publicações por mês (conta a conta, somando todos os times); cada time passa a poder usar até 2.500 também.
  • Contas por time: documentado como sem limite por padrão (já valia desde 15/09, a tabela de Limites é que estava desatualizada).

1.2.0 · 15/09/2026

  • Redes novas: YouTube, Threads, LinkedIn (páginas de empresa), TikTok Business e Bluesky, para conectar, publicar e acompanhar o desempenho.
  • platform_options.youtube (título, privacidade, feito para crianças, tags, categoria e conteúdo gerado por IA) e platform_options.tiktok_business.
  • POST /accounts/connect aceita bluesky.handle e bluesky.app_password.
  • A API recusa texto acima do limite do Threads (500 caracteres) e do Bluesky (300), conta a conta, já considerando caption_overrides.
  • Times sem limite de contas: max_accounts vem null.

1.1.0 · 14/09/2026

  • POST /accounts/connect aceita account_id para reconectar ou pedir de novo as permissões de uma conta que já está no time. Antes, a autorização de uma conta que já existia voltava recusada com External Id already exists for account ….
  • Chaves presas a algumas contas podem reconectar as contas delas (continuam sem conectar contas novas).

1.0.0 · 14/09/2026

  • Chaves de acesso por time: leitura e escrita, só leitura, presas a contas e limite por minuto.
  • Contas (listar, conectar, reconectar, desconectar, remover) e grupos.
  • Biblioteca e upload de arquivos (/media/upload-url), com o tipo reconhecido pelo próprio link.
  • Publicações em Instagram, Facebook e TikTok: agendar, editar, reagendar, cancelar, reenviar e conferir; group_ids, vary_captions, capa de vídeo e dry_run.
  • Variações de legenda (auto, ai, local), Idempotency-Key, desempenho das contas e dos posts, webhooks assinados.

Mudanças que quebram integrações só acontecem numa nova versão (/v2), avisada com antecedência. Novidades compatíveis entram na v1 e aparecem aqui.

Ajuda

Ajuda e suporte

  1. Confira a chave com GET /me.
  2. Teste a publicação com "dry_run": true: a mensagem de erro diz o que ajustar.
  3. Veja o code na tabela de erros e o resultado de cada conta na Fila do painel.
  4. Ainda com problema? Mande para o suporte o X-Request-Id, o horário, a rota, o status e o code. Nunca mande a sua chave.
